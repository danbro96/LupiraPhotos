# LupiraPhotos — agent notes

- BFF pattern: ~/Nextcloud/Familj/DevOps/Guides/bff-pattern.md
- Platform packages (`Lupira.*` NuGet, `@danbro96/lupira-*` npm): ~/Nextcloud/Familj/DevOps/Guides/platform-packages.md. Restore needs `PACKAGES_TOKEN`.
- Deploy config: DevOps `WebApps/lupira-photos-web/` is authoritative; `deploy/compose.yaml` is the genericized example.
- **Purpose**: photo/video library client over photo-api: gallery and timeline, trash, event links (cal relations), and the mobile camera-roll backup. Bytes move between the client and object storage via presigned URLs, never through the BFF.
- **BFF**: `src/LupiraPhotosBff`. Authentik client `lupira-photos` (web) / `lupira-photos-mobile` (bearer, `aud=lupira-photos`), cookie `__Host-lupira-photos`. YARP → `photo-api` `/photo-api`, `cal-api` `/api`, `geo-api` `/geo-api` (prefix stripped, bearer attached). No anonymous surface.
- **Scopes**: base five at `Auth:Oidc:Scopes` 0–4; audience scopes from 5 (compose overrides by index).
- **`/depz`**: one anonymous `readyz` probe per `ReverseProxy:Clusters` entry; `X-Probe-Key` = `Depz:ProbeKey`, blank = off.
- **`exposed.json`**: only what the photo screens and uploader call; no extra groups. geo-api exposes read-only place lookup (`GET /places/suggest`, `GET /geocode/forward`, `GET /places/{id}`, `POST /places/lookup`, `GET /me/places`) for choosing a photo location and naming saved places; photo-api's `PUT`/`DELETE /photos/{id}/location` and `POST /photos/relocate` set, clear and bulk-set it. Mobile gates geo calls on `useGeoReady` (token carries `aud` `lupira-geo`, present only after a sign-in with `lupira-geo-aud`). Unreachable: `/mcp`, `/internal/*`, `/depz`, `/openapi/v1.json`, `/scalar`, `/pingz`.
- **Contract**: `dotnet build` writes `openapi/LupiraPhotosBff.json` from `src/LupiraPhotosBff/upstream/*.json` filtered by `exposed.json`. `dotnet run --project src/LupiraPhotosBff -- --routes` prints the route table.
- **Tests**: `dotnet test LupiraPhotosBff.slnx` = unit only; `dotnet test tests/LupiraPhotosBff.IntegrationTests` (in-process stub upstream, no Docker).
- **Workspaces**: `packages/api` (`@lupira/photos-api`, orval, `query/*` + `fetch/*` over one models dir), `packages/domain` (`@lupira/photos-domain`, pure TS consumed as source, no generated DTO types), `packages/tokens` (`@lupira/photos-tokens`, the palette: estate core + warning/success), `apps/web`, `apps/mobile`. Shared modules come from `@danbro96/lupira-*` (domain-core/events/places/photos/links, tokens-core, http, web-mui/session, expo-paper/feedback/diagnostics/oidc/sqlite).
- **Web** (`apps/web`): MUI SPA, conventions in ~/Nextcloud/Familj/DevOps/Guides/frontend-estate.md. `PhotosScreen` is `/`; filters and the viewer ride URL params (`?photo=`, `?event=`, `?from&to=`, …). Cookie transport (`installCookieTransport`), `RequireAuth` from `@danbro96/lupira-web-session`. Layers `data → state → ui` + leaf `config/`. Sibling links via `config/siblings.ts` (`VITE_CAL_URL`/`VITE_MAPS_URL`/`VITE_PHOTOS_URL`; dev = Vite ports 5174/5175/5176, build = `https://*.lupira.com`). Vite proxy list mirrors the cluster prefixes the SPA calls.
- **Mobile** (`apps/mobile`): Expo 57 "Lupira Photos", package `com.lupira.photos`, scheme `lupiraphotos`, Authentik client `lupira-photos-mobile`, Android only. Read path: hand-written hooks over the generated fetchers under `['photos', …]`, gated on connectivity, persisted by `PersistQueryClientProvider` to `expo-sqlite/kv-store` (allowlist: list/detail/stats/places). SQLite (`lupira-photos.db`) holds only `photo_upload_queue` + `meta`. Layers `domain → data → sync → state → ui`; `sync` = uploader + background task only. Deep links `lupiraphotos://event/{id}`, `lupiraphotos://photo/{id}` and the `appLinks` query forms.
- **Read before touching**: `docs/photos.md`.
- Dev ports: BFF 5183, Vite 5176. Prod: photos.lupira.com:42281, image `danbro96/lupira-photos-web`.
